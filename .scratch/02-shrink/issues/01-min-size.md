## Issue

用户第 28 轮：v17 引擎已有真实物理，用**缩小实验**找最小车长。两条硬要求（用户口述）：

1. 前 / 后溃缩梁长度**适中**（不能为了缩车把溃缩梁压到零）。
2. **大床模式 ≥ 1800**（现行 C6 是两床一律 ≥1750）。

## 结果（详细推导见 `docs/design/结构决策.md` D61）

- **恒等式**：`L = (x10+x11) + 床长`；`床长 = (x12+x13+x14) + 740 + C13余量 + x04`；
  躺姿头部约束 `C13余量 + x04 ≥ 890` ⟹ **L_min = (座舱链 Sb)min + 1630**。
  实测每个场景都正好落在这条线上（S0/S1/S2/S3 的"头到车尾余量"都是 890）。
- **要求 1（前梁）**：1:1 计费，`L = 3630 + x00`（200→3830 / 300→3930 / 420→4050 / 500→4130 / 600→4230）。
  **要求 1（后梁 x04）**：≤890 免费，超过才 1:1（x04=900 → 3940）。
- **要求 2（大床 ≥1800）**：**不卡**。床长 = (x12+x13+x14)+1630 ≥ 2330（滑块下限给的），
  把要求提到 2500 结果一样。
- **最小车长**（八预设硬判据全绿）：今天的人机空间 **3930** · 紧凑 **3570** · 更紧 **3470** ·
  无人工下限 **3020**（现状 4260）。
- **引擎缺陷**：`x15 = 0`（合法滑块值）时 `inflate()` 出 NaN → `pushOutPoint()` 抛异常；未修。
  C16 报错不说是哪一端/哪个粒子（实际每次都死在「超出 床面·头」）。

## 验收标准（对本次交付）

1. `node scripts/shrink.mjs` 输出「最小 L + 恒等式分解 + 每个参数再缩 10mm 死在哪条判据」。
2. 搜索确定性：同参数跑两次结果一致（坐标二分 + 随机多参数下降的混合，每步落点都真的过判据）。
3. 结果看图确认（附 S0 / S1 的 PNG）。
4. 把结论写进 D61（含发现的引擎缺陷与四个待裁定口径）。

## Comments

- 实验过程中的一个自身缺陷（已修）：只做坐标二分会卡在"两三个参数必须同时缩"的角上，
  且早期版本会把二分出来的**未验证**的边界值当结果（曾报出一个全绿=false 的假解）。现在的
  混合搜索对每个接受的落点都重新跑完 8 个预设。
- 引擎侧发现：**判据表里没有任何"人体空间"下限**（脚空间 / 座垫长 / 电池容量只有滑块下限），
  所以"最小车长"这个问题的答案**必须**带上人工下限一起说，否则会给出退化解（3020）。
  这正是 D61 里那四个待裁定问题的来源。
- 触发本次实验的两个要求（梁长、大床 1.8）在引擎里都**不是**卡点；真正卡住车长的是
  「躺姿的人头必须留在车里」（890）与「座舱链 Sb」。
