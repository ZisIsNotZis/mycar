## 一、你报的 4 件事：全部复现，原因都已定位

### 1. 靠背角度与人体反向 —— 确定，是符号错误

- 靠背顶：`X(rCush1 + rBl·sin(rBa))` → 正角度朝**车尾**倒（对）。
- 人体躯干：`rTorsoDir=[sin(rBa), cos(rBa)]` 传给 `seatedJ(..., face=-1)`，函数内 `tx = hip.x + torsoDir.x·540·face` → face=-1 把它翻向**车头**（错）。
- 后果不是"轻微"：`rBa=45°` 时人头前移 382mm，而靠背顶后移 396mm —— 两边反向拉开 778mm。
- 同一函数里手臂也用了 face：手被画到 `hip.x + 240`（靠背**后面**，见 audit-1 图右下那条粉色手臂）。

### 2. 二排人体的大腿也和坐垫反向（同一个"两套约定"病根）

前排：`fKnee.y = fHip.y + 420·sin(fCa)` → 膝高于髋（与"坐垫前缘抬高"一致，正确）。
二排：`rHip.y = rKnee.y + 420·sin(rCa)` → 髋高于膝（与坐垫前缘抬高**相反**）。
错位量 = `420·sin(rCa) + 490·sin(rCa)`：默认 5° 就错 79mm，`rCa=30°` 错 455mm。

### 3. 升顶：三处独立缺陷叠加

| 现象 | 实测 |
|---|---|
| "睡人"整块飘在车顶之上 | 人体几何 y=2092–2371；原车顶 1660、升顶面 1960 → 整个人在车外 |
| 躺姿人形**头身分离** | 头心 3860，躯干末端 2919 → 断口 940mm。`lying()` 把脖子的 x 算成 `px-cos(楔角)·(全长·0.55)·sc`，头圆却画在 `px`；躺床模式下同样（头飘在尾门处，见 audit-2 右侧红圈） |
| 开口只有 600 宽且跟着二排座椅跑 | `x = [rCush0-200, L-1200]` = 2110–2710；拖二排座椅，车顶开口跟着动 |
| 升顶抬高 `pr` 上限 450 不够用 | 站姿要站在床面 660 上：头顶 = 660+1750 = 2410，顶棚需 ≥2450 → `pr ≥ 2450−H`；H=1900 时需 550。**这就是"范围太小"** |

### 4. "整体看起来怪"的根因：单位混乱 + 图层混淆

- **单位混用**：该乘 `sc` 的地方没乘、该用像素的地方乘了 `sc`。坐垫/靠背一律画 `18*sc`/`16*sc` → 世界 **16–18mm** 的纸片，而滑块写着"坐垫厚 220"；`坐垫厚` 滑块只把**人**往上抬，坐垫本身不厚。
- **轮包弧心画在地面**（`Y(gc)`）而不是轮心 → 包顶 **524mm**，而轮顶 **678mm**：轮包整个装在轮胎肚子里（audit-1 左侧红圈）。
- **外扩件与中心线件画在同一张不透明图上**：侧视图本质是**中心线剖面**（地板 440、电池、座椅、人是中线件），轮胎/轮包属于**车外两侧**。v11 把两组都画成不透明实体并叠加 → 看起来像"电池和脚插在轮子里"。
  **更正**：我最初把这条报成物理错误，是错的。3D 上两者并不打架（电池宽 = W−410，双脚在左右轮包之间）。真正的缺陷只是**画法**：外扩件应当用虚线/半透明"幽灵层"表示，中线件才是不透明剖面；相应地把"电池避开前轮包"从侧视 x 判据降级为**宽度判据**（电池宽 ≤ 左右轮包内间距）。

## 三、"约束基本无解"——滑块难调的真正原因

用 v11 自己的 17 条校验做 20000 次全参数域随机采样：

```
全绿样本：1 / 20000    且那一个必须 L=4800
失败频率 Top5：波峰 18932 · 床链 16856 · 前垫避轮包 12332 · 后轴在二排区 11855 · 电池后缘 10769
```

**波峰** 和 **床链** 两条就是上面第 1、2 号错误。把它们修正（床长改成"全平床面 = L−腿托前端"，波峰只算尾台区）后重新采样：

```
L=3500 全绿解存在，例如：
L3500 W1990 H1560 xF1480 fCl375 xR1670 rCl670 rLl180 rBl570
axF610 axR2220 tdf662 tdr624 gf135 gr175 bt310 rCt250 …
```

**结论：不是滑块范围小，是两条写错的检查把车强行撑到 4.8 米**——而"极小外轮廓"是说明书 1.1 的第一条定位。修好后 3.5 米就有解。

## 四、工具能力缺口（"没法在里面调审美"）

| 缺什么 | 后果 |
|---|---|
| 没有数字输入框 | 只能靠拖，±1 的角度/±5 的长度对不准 |

| 没有版本管理 | 目录里 12 个 HTML、git 零提交 —— 任何一次覆盖都不可恢复 |
